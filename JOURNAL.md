## 2026-08-14 — Phase 5: первый реальный деплой на romkin.blog

- Параллельно с этим — закрыли Вариант 3 ДЗ №11 курса по вайб-кодингу
  («задеплой свой проект»), см.
  `../../job-search/WorkHunter/courses/vibe-coding-claude-code/homework/hw-11-deploy.md`
  для полного разбора. Здесь — только специфичное для проекта.
- **Находка перед началом работы:** `www/README.md` в `WorkHunter` утверждал
  «хостинг и git пока не настроены» — оказалось устарело. `romkin.blog`
  уже был живой (DNS, HTTPS, домен куплены раньше, заглушка отдавалась с
  реального хостинга). FTP-порт был открыт, доступы нашлись в панели
  хостинга — экономия целой фазы «купить хостинг».
- Хостинг — `nichost.ru`, путь на сервере `/romkin.blog/docs/`. Этот путь
  совпал 1:1 с тем, что уже было прописано в
  `../romkinblogsimple/.github/workflows/main.yml` — значит текущий и
  прошлый проект физически делят один и тот же хостинг-аккаунт.
- **Проверка перед деплоем: SSG действительно статический.** Несмотря на
  `routeRules: { '/': { ssr: true } } ` в `nuxt.config.ts`, было
  сомнение, не потребуется ли `ssr: false`. Проверили руками:
  `nvm use 24 && npx nuxi generate`, затем подняли результат через
  `npx serve .output/public` — все маршруты отдают готовый, полностью
  отрендеренный HTML (не пустой SPA-shell под гидратацию). `ssr: true` в
  routeRules — это про то, как краулер рендерит маршрут во время сборки,
  не про рантайм-зависимость от сервера. Трогать не пришлось.
- Workflow адаптирован из `romkinblogsimple`, но не скопирован дословно:
  Node 20 → 24 (CLI Nuxt использует `node:util.styleText`, которого нет в
  Node 20.10 — та же причина, что и в `CLAUDE.md` для локальной разработки),
  убраны хаки вокруг `better-sqlite3` (там это была проблема разрешения
  версий, здесь — обычная зависимость в `package.json`).
- Осознанно исключили `**/backup/**` в FTP-деплое — на сервере в
  `docs/backup/` лежит что-то от старой версии сайта, не должно
  пострадать от синхронизации. Проверили заранее (не наугад): по
  документации `SamKirkland/FTP-Deploy-Action` дефолтное поведение и так
  не трогает файлы, не отслеживаемые state-файлом действия (первый деплой
  ничего не удаляет, `dangerous-clean-slate` по умолчанию `false`) — но
  явный exclude оставили как дополнительную страховку.
- **Грабли #1:** `git push` с новым `.github/workflows/main.yml` упал —
  `refusing to allow an OAuth App to create or update workflow ... without
  'workflow' scope`. У локального `gh` CLI токена не было scope
  `workflow`. Чинится `gh auth refresh -s workflow` — но это device flow,
  нужно подтверждение в браузере, не бесшовно.
- **Грабли #2:** первый реальный прогон Actions упал на самом FTP-шаге —
  `530 Login incorrect`. Секреты `FTP_PASSWORD`/`FTP_USERNAME`, вписанные
  с первого раза, не подошли (опечатка при копипасте или не тот пароль).
  Перевписали — второй прогон прошёл зелёным целиком.
- **Итог проверен не на глаз, а по факту:** `content-length` живой
  `https://romkin.blog/` (69291 байт) сверен с размером локально
  собранного `.output/public/index.html` — совпал байт в байт, значит на
  сервере действительно та сборка, которую тестировали, а не что-то
  промежуточное.
- **Не наша поломка, но заметили:** редирект `/cv` → `/cv/`, который
  генерирует сам хостинг (не Nuxt/не этот workflow), уходит на `http://`,
  не `https://`. Не блокирует (страница всё равно открывается), но если
  когда-то будет странно ругаться на mixed content — вот источник.

**Что дальше (не сделано сегодня, зафиксировано как открытое):**
staging на `dev.romkin.blog` (сейчас есть только прод), архивация
`romkinblogsimple` (требует отдельного подтверждения), актуализация
`CLAUDE.md`/`PRD.md` — они всё ещё пишут «домены не задеплоены», это
устарело после сегодняшнего дня. Полный список — в §5
`hw-11-deploy.md`.

## 2026-08-14/15 — Контент, полировка и один настоящий инцидент

Продолжение того же дня/ночи после первого деплоя выше — контентная
чистка и несколько находок по факту того, что сайт наконец реально
публичный.

- **Контент:** `zamykaniya-v-js` (слишком банальный) и
  `event-loop-blocking-tradeoffs` (слишком сырой, недоработанный) —
  перенесены обратно в `post-drafts/` (не удалены). Для трёх оставшихся
  опубликованных постов сгенерированы настоящие обложки через
  `generateCoverPng` вместо общего `placeholder.png` — они были портированы
  напрямую в `content/post/`, минуя `post-drafts/`, поэтому раньше не
  проходили через генератор обложек.
- **Дизайн:** акцент на точке в логотипе шапки (`romkin.blog`) — сверялись
  со скиллом `frontend-design`: сознательно только точка, не буквы «o» —
  на сдержанном editorial-дизайне один точный акцент читается лучше
  нескольких decorative.
- **Баг: 500 вместо 404 на любой отсутствующей странице.** Старый
  `.htaccess` (жил только на сервере, вне git) содержал
  `RewriteRule ^(.*)$ $1.html [L]` без защиты от повторного применения —
  для несуществующих путей уходил в петлю внутренних редиректов
  (`path` → `path.html` → `path.html.html` → …) до лимита Apache. Правило
  раньше никогда не проверялось на реальном отсутствующем пути — всегда
  попадало на существующий `.html` с первого раза. Файл теперь
  version-controlled (`public/.htaccess`), правило починено условием
  `RewriteCond %{REQUEST_URI} !\.html$`.
- **Своя 404-страница** (`app/error.vue`, в общем layout) + `ErrorDocument
  404 /404.html` вместо дефолтной страницы хостера. Оговорка: на статике
  Nuxt отдаёт `404.html` пустой SPA-оболочкой — контент виден после
  загрузки JS, не мгновенно. Полностью статический рендер (кастомный
  Nitro-хук) сознательно не стали делать — сложность не оправдана для
  этого масштаба.
- **Более серьёзная находка: `/cv` показывал старую версию.** Рядом с
  новым `docs/cv.html` (Nuxt) на сервере всё ещё лежала старая статическая
  папка `docs/cv/` (прошлая итерация резюме) — деплой её не трогал (не
  удаляет то, что сам не заливал), и Apache резолвил именно её первой.
  Реальные посетители `/cv` никогда не видели новую версию. Роман удалил
  старую папку вручную на сервере — теперь `/cv` резолвится в `cv.html`
  напрямую.
- **Дёргающаяся вёрстка список↔статья:** скроллбар то появлялся, то
  исчезал в зависимости от высоты страницы, место под него не было
  зарезервировано — `mx-auto`-контейнер прыгал вбок. Фикс —
  `scrollbar-gutter: stable`.
- **Инцидент: сломанный HTTP→HTTPS редирект положил весь сайт.** Попытка
  добавить `RewriteCond %{HTTPS} off` → редирект на https — этот хостинг
  терминирует TLS на прокси (openresty) перед Apache, поэтому `%{HTTPS}`
  внутри Apache **всегда** `off`, даже для запросов, реально пришедших по
  HTTPS. Правило приняло уже защищённый запрос за незащищённый и
  редиректило само на себя — бесконечная петля на несколько минут по всем
  страницам сайта. Откатили сразу (`git revert` + пуш). Урок: любая логика
  в `.htaccess`, завязанная на протокол/IP клиента, ненадёжна за
  reverse-proxy без проверки `X-Forwarded-*`-заголовков — а какой именно
  заголовок реально прокидывает openresty на этом хостинге, не выяснено.
  HTTP→HTTPS редирект остался открытой задачей — делать только после
  уточнения у поддержки `nichost.ru`, не проверять экспериментом на проде.

**Актуальный список открытого** (не изменился по сути, но добавился пункт
про редирект) — см. §5 `hw-11-deploy.md`, актуализирован тем же днём:
staging `dev.romkin.blog`, архивация `romkinblogsimple`, generator-v2,
судьба `docs/backup/`, актуализация `CLAUDE.md`/`PRD.md`, аналитика,
Telegram-анонс, HTTP→HTTPS редирект (после уточнения у поддержки).
