## 1. Контекст и цель

Уже есть две попытки блога на Vue/Nuxt (`romkinblog`, `romkinblogsimple`) и параллельно
в разработке React/Next.js-версия (`romkinblog-react`) — она задумана как основная
учебная площадка (практика React), но идёт медленно из-за загрузки поиском работы,
курсом Claude Code и подготовкой к собеседованиям.

Этот проект — способ получить **рабочий блог быстро**, не дожидаясь React-версии:
Nuxt/Vue уже знаком, писать статьи и развивать личный бренд нужно уже сейчас, в процессе
подготовки к собеседованиям. В будущем предполагается, что React-версия догонит и
продублирует функционал этого блога как «совместная версия для обучения» — тогда
этому Vue-блогу, вероятно, понадобится освободить домены или переехать на отдельный
поддомен (см. §10).

Ключевое отличие от `romkinblog-react`: там цель наполовину учебная (практика React),
здесь цель практическая — рабочий результат, реализация в основном силами Клода.

## 2. Цели

- **Практическая**: рабочий блог на `romkin.blog`, публикация статей через
  «закинул md + картинки → сгенерил → git push» без админки и бэкенда.
- **Сохранить задел на будущее**: содержательная связь и совместимость с
  `romkinblog-react` (общий дизайн-язык, возможность позже продублировать функционал).
- Документация должна оставаться живой — обновляться при изменении решений
  (см. `CLAUDE.md`).

## 3. Область действия

**Референсы (см. отчёт разведки в истории разговора):**
- `romkinblogsimple` — архитектурный референс (Nuxt 3 + `@nuxt/content` v3 + Tailwind +
  `@nuxtjs/color-mode`). **Не копировать целиком**, но конкретные уже рабочие
  куски стоит переиспользовать почти как есть: `content.config.ts` (zod-схема),
  shortcode `::BlogImage{...}` → `BlogImage.vue`, `Common/Avatar.vue` (hover-scale),
  `Header/Main.vue`, `Posts/Card.vue`, `Posts/Pagination.vue`.
- `romkinblog-react` — источник дизайн-токенов и тестовых статей (5 mdx-статей в
  `content/posts/`). У него уже есть собственный `PRD.md`/`AGENTS.md` — см. §10,
  конфликт по доменам.

**Домен и хостинг — важная поправка после разведки:**
`WorkHunter/www/README.md` прямо говорит: «Хостинг и git пока не настроены».
`romkin.blog/` и `dev.romkin.blog/` сейчас — только локальные HTML-заглушки
(смотрятся через `python3 -m http.server`), нигде не задеплоены. FTP-workflow в
`romkinblogsimple/.github/workflows/main.yml` деплоит в `/romkin.blog/docs/` —
похоже на артефакт прошлой, отличной от текущей схемы хостинга.
Значит «восстановить хостинг» на практике означает **настроить с нуля** —
это работа Романа (см. `crude-idea.md`), проект должен быть готов принять
рабочие FTP/деплой-секреты, когда они появятся.

**`/cv` — в scope этого проекта (решено 2026-08-13):**
`WorkHunter/www/README.md` помечал миграцию `/cv` на Nuxt как решение,
требующее явного запроса от Романа — запрос получен, `/cv` переносится сюда
как Nuxt-страница/роут. Источники контента остаются в `WorkHunter` (не
копировать данные — читать/синхронизировать при генерации):
- `WorkHunter/resume/frontend.md` — текст резюме.
- `WorkHunter/www/romkin.blog/cv/assets/photo-edited.jpg` — фото (используем
  edited-версию, та же, что уже на текущей статической странице).
- `WorkHunter/www/romkin.blog/cv/assets/roman-palmin-frontend-resume.pdf` —
  скачиваемый PDF (не hh.ru-версия, см. `WorkHunter/resume/analysis.md`).
- Осознанно не публикуется: зарплатные ожидания, телефон (см.
  `WorkHunter/profile/hr-narrative.md`) — то же ограничение, что и сейчас.
- Старая статическая версия в `WorkHunter/www/romkin.blog/cv/` — после
  переноса становится избыточной (решить отдельно, когда дойдём до
  деплоя: удалить/оставить как fallback).

## 4. Визуальный дизайн

Переносим токены из `romkinblog-react/src/app/globals.css` (не изобретаем заново):

| Токен | Light | Dark |
|---|---|---|
| `--bg` | `#faf9f6` | `#121214` |
| `--text` | `#17181c` | `#f3f2ee` |
| `--accent` | `#a8460f` | `#e8964c` |

Шрифты: Fraunces (display) / IBM Plex Sans (body) / IBM Plex Mono (код).
`--radius: 3px`, `--container: 1080px`. Тема — атрибут `data-theme` на корне,
реализация в Vue через `@nuxtjs/color-mode` (уже используется в `romkinblogsimple`,
даёт тот же паттерн, что `next-themes` в React-версии: persist в `localStorage`,
по умолчанию системная тема).

**Переключатель темы**: повторить UX `romkinblog-react/src/components/theme-toggle.tsx`
(кружок 32×32, ☾/☀) — адаптировать под `@nuxtjs/color-mode`.

**Шапка**: переиспользовать структуру `romkinblogsimple/app/components/Header/Main.vue`
как основу. Разделы: `LIVE` (все статьи), `Frontend`, `Dev` (фронт + разработка + AI),
`AI` → ссылки на `romkin.blog/category/[categoryName]`. `LIVE` = сама `/`
(лента без фильтра, отдельного `/category/live` не заводим — дефолт,
не спрашивалось отдельно). Справа — компонент аватара (`Common/Avatar.vue`
уже даёт нужную механику: `hover:scale`), клик ведёт на внутренний роут
`/cv` (теперь часть этого Nuxt-приложения, см. §3), фото —
`photo-edited.jpg` (дефолт: та же фотография, что уже используется на
текущей статической `/cv`-странице, не «сырой» `photo.jpg`).

**Теги**: отображаются как обычные (некликабельные) лейблы у поста/в карточке.
`romkin.blog/tag/[tagName]` строится уже в MVP (страница существует и
отдаёт контент по тегу), просто нигде в UI на неё нет прямых ссылок —
дешевле сделать сразу, чем оставлять полуготовый маршрут (дефолт).

## 5. Технический стек

| Слой | Выбор | Комментарий |
|---|---|---|
| Фреймворк | **Nuxt 3** | как в `romkinblogsimple` |

| Стили | **Tailwind** | не было явно запрошено в исходной идее — выведено из обоих референсов (используется и в `romkinblogsimple`, и в `romkinblog-react`), конфиг переносится, токены — из `romkinblog-react` |

| Иконки | `@nuxt/icon` | как в референсе |

## 6. Контент-модель (frontmatter)

Наследуется из `romkinblogsimple/content.config.ts` («формат статьи и форматтер
как был раньше», по прямому запросу), возможные добавления — по необходимости:

```
title, headline, date, excerpt/excerption, description,
image, imageTitle, imageAlt, imageCaption,
tags: string[], categories: string[], author,
slug (из имени файла или явно)
```

`categories` — свободный список (как в `romkinblog-react`), но с продвигаемыми
в шапке значениями `frontend | dev | ai` (+ `LIVE` = все статьи без фильтра,
см. открытый вопрос про `/` vs `/category/live`).

Задел на будущее (поля, не реализуются сейчас, только резервируются в схеме):
`telegramMessageUrl?: string` — для будущей кнопки «Обсудить в телеграм».

## 7. Функциональные требования (MVP)

- `/` — список статей, пагинация, **настраиваемое количество карточек на странице**
  (конфиг-константа, дефолт 9 — 3×3 сетка, не спрашивалось отдельно).
- `/category/[categoryName]` — LIVE / Frontend / Dev / AI.
- `/tag/[tagName]` — строится в MVP, без прямых ссылок из UI (см. §4).
- `/post/[slug]` — страница статьи, `::BlogImage` в контенте.
- `/cv` — резюме, перенесённое из статического `WorkHunter/www/romkin.blog/cv/`
  (см. §3), тот же дизайн-язык, что и остальной блог.
- Шапка: nav-ссылки + переключатель темы + аватар (hover-scale → `/cv`).
- OG/Twitter meta-паритет со старой реализацией (`title`, `description`,
  `og:*`, `twitter:*`, `article:published_time`, `keywords` из tags) —
  переносится из `romkinblogsimple/app/pages/post/[...slug].vue` почти
  дословно, через `useHead`.
- **Генератор постов**: CLI-скрипт (`npm run generate-post`, запуск руками —
  дефолт, watch-режим избыточен для git-based флоу без админки), которого
  нет ни в одном из референсов (нужно строить с нуля). Флоу: staging-папка
  с `.md` + картинками → скрипт обрабатывает картинки (оптимизация/ресайз,
  копирование в нужный путь), валидирует frontmatter по zod-схеме,
  генерирует финальный `.md` в `content/post/`. Обложка/превью — если не
  указаны явно, автогенерация шаблоном «заголовок на фоне» в токенах
  дизайна (accent/bg цвета, Fraunces) — дефолт, простой и без внешних
  AI-сервисов; подробный подход (canvas/Satori-аналог под Node) —
  на усмотрение при реализации Phase 2.
- **Деплой**: GitHub Actions по образцу `romkinblogsimple/.github/workflows/main.yml`
  (FTP), но с исправленным `server-dir` (не `/romkin.blog/docs/` — нужно
  согласовать реальный путь с Романом при восстановлении хостинга) и с
  исключением `/cv/` из перезаписи. Push в `dev` → `dev.romkin.blog`,
  push в `main` → `romkin.blog`.

### Осознанно не в MVP

- Реальная отправка анонса в Telegram (см. `WorkHunter/.claude/skills/blog-to-social`
  — уже есть скилл генерации текста анонса из MDX для React-пути, адаптировать
  под Vue-контент позже) + кнопка «Обсудить в телеграм» на странице поста.
- Полноценный предварительный деплой на `dev.romkin.blog` с ревью-флоу —
  на первом этапе `dev` может быть просто вторым окружением без доп. процесса.
- Отдельный поддомен и деплой-агент для React-версии, когда она догонит.
- Учебный разбор в `WorkHunter/courses/romkinblog-vue` (аналог
  `WorkHunter/courses/romkinblog-react`) — завести, когда стабилизируется код.

## 8. Архивация `romkinblogsimple`

⚠️ **Требует явного подтверждения перед выполнением.** Это чужой (по
отношению к новому проекту) git-репозиторий с деплой-секретами
(`FTP_SERVER/FTP_USERNAME/FTP_PASSWORD` в GitHub Actions) и потенциально
живым FTP-таргетом.

Найдено при разведке: на `main` сейчас есть **незакоммиченные изменения**
(`.gitignore`, `tailwind.config.js` изменены; `audit-dashboard.html` не
отслеживается) — их нужно разобрать до архивации (см. §10).

Предполагаемые шаги (не исполнять без апрува):
1. `git checkout main && git pull`
2. Разобраться с незакоммиченными изменениями (закоммитить в архив как есть
   или отбросить — решение Романа)
3. `git checkout -b archive/pre-vue-rewrite` (имя — предложение, можно другое)
4. `git push origin archive/pre-vue-rewrite`
5. Очистить `main` (способ — orphan branch или явный revert — уточнить)
6. То же для `dev`
7. Начинать разработку нового Nuxt-проекта поверх очищенных `main`/`dev`,
   сохраняя текущий GitHub Flow (push в `dev`/`main` триггерит деплой)

## 10. Открытые вопросы

Всё блокирующее и большинство мелких пунктов решены 2026-08-13 (см. врезку
в начале файла и решения по тексту документа). Символическая ссылка
`WorkHunter/www/romkinblog-vue → dev/personal-projects/romkinblog-vue`
заведена по аналогии с `romkinblog-react`.

Остаётся уточнить (не блокирует старт разработки, всплывёт по ходу фаз):
1. **Реальный `server-dir` для FTP-деплоя** — текущий в `romkinblogsimple`
   (`/romkin.blog/docs/`) выглядит устаревшим; точный путь узнаем у Романа,
   когда он настроит хостинг (Phase 4/5). `.github/workflows/main.yml` из
   `romkinblogsimple` берём как основу и адаптируем (файл — не секрет,
   переносится свободно). Секреты `FTP_SERVER/FTP_USERNAME/FTP_PASSWORD`
   **не наследуются** между репозиториями (даже на одном аккаунте — GitHub
   Actions secrets write-only, organization-level sharing недоступен на
   личных аккаунтах) — Роман вбивает их заново вручную в Settings этого
   репозитория на Phase 5.
2. Судьба старой статической `/cv` в `WorkHunter/www/romkin.blog/cv/` после
   переноса на Nuxt — удалить, оставить как fallback, или использовать как
   образец вёрстки и удалить после сверки.
3. Аналитика (Plausible/Яндекс.Метрика/ничего) — не обсуждалось, по
   необходимости.
4. Дефолтная OG-картинка, если у статьи нет своей обложки (в
   `romkinblogsimple` была захардкожена `https://romkin.blog/default-og-image.jpg`).
